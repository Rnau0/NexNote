# 路线图

## 阶段一：可运行的骨架（v0.1.0 · 已完成）

目标：把"数据链路"跑通，让后面的 PDF 层有东西可以挂。

- [x] Obsidian 插件工程（TypeScript + esbuild + 官方 sample plugin 结构）
- [x] 插件入口、`manifest.json`、`styles.css`、设置页
- [x] 右侧栏 AI 助手（可打开、多轮对话、可清空）
- [x] 模型提供商 / API Key / 模型名 / API 地址 / 温度 / 最大长度配置 + 测试连接
- [x] 独立知识卡片模型（父子、分支、状态、锚点预留）
- [x] AI 服务接口（`AIProvider` + `HttpClient` 注入，可换实现）
- [x] 引用系统（选中文字 → 引用到提问框）
- [x] 卡片内独立聊天框 + 存为子卡片
- [x] 卡片库 JSON 存储与损坏保护
- [x] 构建脚本、`.gitignore`、README、架构/开发文档
- [x] core 层单元测试（卡片、存储、AI 客户端、引用、设置迁移）

明确不在本阶段：PDF 虚线、知识画布、OCR、手写笔迹迁移。

## 阶段二：回到原文（PDF 层）

- [ ] PDF 阅读视图（优先复用现有 PDF 插件能力，不自研渲染内核）
- [ ] 页码 / 文本块 → 屏幕坐标映射（**Codex 主导**：复杂坐标定位）
- [ ] 原文下方绘制可点击虚线，点击弹出对应卡片
- [ ] 知识点"少量精准"筛选的二次校验（模型给候选 → 规则/阈值再筛）
- [ ] 卡片与原文双向跳转
- [ ] 圈选区域作为"AI 未识别内容"的兜底入口
- [ ] 与 Ink-Annotation 手写批注共存（不迁移笔迹，只共享文档视图）

## 阶段三：知识与画布

- [ ] 知识画布视图（卡片作为节点，父子/分支关系作为边）
- [ ] 跨文档知识关联（相同概念自动聚合）
- [ ] 卡片导出为 Markdown / Anki 兼容格式
- [ ] 学习轨迹（哪些卡片看过、追问过几次）

## 阶段四：独立 App

- [ ] 抽取 `src/core` + `src/services` 为独立包（npm workspace 或 monorepo）
- [ ] Android 客户端（优先跑通鸿蒙平板的安卓兼容环境）
- [ ] 与 Obsidian 端共用同一份 JSON 数据格式
- [ ] 同步方案（用户自选：文件夹同步 / WebDAV / 本地）

## 已知问题 / 技术债

| 问题 | 影响 | 计划 |
| --- | --- | --- |
| 无流式输出 | 长回答要等整段返回 | 阶段二评估 `AIProvider.streamChat` |
| 卡片尚未与 PDF 坐标绑定 | 目前靠"选中文本 → 生成"驱动 | 阶段二 |
| 卡片库全量读写 | 上万张卡时可能变慢 | 阶段三分片或换 SQLite |
| 卡片树只做单层渲染 | 深树需逐层点开 | 阶段三做画布时统一解决 |
